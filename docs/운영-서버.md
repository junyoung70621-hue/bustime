# 회사 서버 운영 안내 (bustime / myapp)

## 구성

| 항목 | 위치 |
|---|---|
| 앱 | 도커 컨테이너 `myapp` (서비스 `web`), `http://<서버주소>:8090` |
| DB | 도커 컨테이너 `myapp-db` (Postgres 17, 데비안 판 — CentOS 7 서버라 alpine 판 불가), 볼륨 `myapp_pgdata`, **외부 포트 없음** |
| PDF·증빙사진 | 볼륨 `myapp_data` → 컨테이너 안 `/app/data/files/{daepyecha,checklist}` |
| 팀즈 인라인 캡처 이미지 | Supabase `captures` 버킷 (예전 팀즈 글 이미지 유지용으로 계속 사용) |
| 스케줄·백업 | 서버 crontab (`deploy/crontab.txt`) |
| 소스 | `~/bustime_atec` (GitHub `bustime_atec`, Private) |

## 업데이트 (코드 바꾼 뒤)

```bash
cd ~/bustime_atec
git pull
docker compose up -d --build
```

## 자주 쓰는 명령

| 하고 싶은 것 | 명령 |
|---|---|
| 상태 | `docker compose ps` |
| 앱 로그 | `docker compose logs -f web` |
| DB 접속 | `docker compose exec db psql -U app app` |
| 스케줄 기록 | `tail -50 ~/myapp-cron.log` |
| 백업 목록 | `ls ~/myapp-backup` |

⚠️ `docker compose down -v` 는 **DB와 파일 볼륨까지 지웁니다.** 절대 `-v` 붙이지 마세요.

## Supabase → 회사 서버 전환 절차 (1회)

> 지금 사용자들은 `https://bustime-beta.vercel.app`(Vercel+Supabase)을 씁니다.
> 아래 8번(Vercel 리다이렉트)을 하기 전까지는 사용자에게 아무 영향이 없습니다.

### ⚠️ 푸시 규칙 (전환 전까지 반드시)

PC 저장소에는 원격이 둘 있습니다.

| 원격 | 저장소 | 푸시하면 |
|---|---|---|
| `atec` | `bustime_atec` (Private) | 회사 서버가 `git pull` 로 받음 |
| `origin` | `bustime` (Public) | **Vercel 이 즉시 자동 배포** |

- 이 전환 코드(브랜치 `selfhost-db`)는 DB·파일을 회사 서버에서 찾기 때문에 **Vercel 에 올라가면 모든 저장·조회가 오류**가 납니다.
- 그래서 **8번 전에는 `git push origin main` 금지.** 서버용은 `atec` 에만 올립니다.
  ```powershell
  git checkout main
  git merge selfhost-db
  git push atec main        # origin 에는 올리지 않음
  ```
- 8번 이후에는 origin 에 올려도 됩니다(Vercel 은 모든 주소를 회사 서버로 넘기기만 함).

### 전날 (사용자 영향 없음)

1. **서버에 새 버전 올리기**
   ```bash
   cd ~/bustime_atec
   git pull
   nano .env   # 아래 3줄 추가/수정
   ```
   - `POSTGRES_PASSWORD=` ← `openssl rand -hex 16` 으로 만든 값 (한 번 정하면 바꾸지 말 것)
   - `SUPABASE_URL=https://<ref>.supabase.co` (예전 `NEXT_PUBLIC_SUPABASE_URL` 값)
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` 줄은 삭제
   ```bash
   docker compose up -d --build
   docker compose ps          # myapp, myapp-db 둘 다 Up (healthy)
   docker compose exec db psql -U app app -c '\dt'   # 테이블 5개가 보여야 함
   ```
   - 테이블이 안 보이면(SELinux 등으로 `db/init.sql` 을 못 읽은 경우) `docker compose logs db` 확인 후
     `docker compose exec -T db psql -U app app < db/init.sql` 로 직접 만든다.
   - ※ 지금 `:8090` 을 쓰는 사람이 있다면 이때부터 전환 때까지 빈 화면이 보이고, 거기 저장한 건은 4번에서 지워진다.
2. **PDF 파일 미리 받기** (오래 걸림, 끊겨도 다시 실행하면 이어받음)
   ```bash
   docker compose exec -T web node scripts/migrate-storage.mjs
   ```
2-1. **휴대폰 실기 확인 (http 에서 사진 업로드)** — 당일 중단 시간에 처음 발견하지 않도록 전날 해 둔다.
   - 휴대폰으로 `http://<서버주소>:8090` → 로그인 → 수도권 설치완료 체크리스트 신규 작성 → **증빙사진 8장** → 저장.
   - 팀즈 센터 폴더·사진 폴더·스레드(인라인 이미지)에 올라오는지 확인 → 확인 후 팀즈에서 테스트 글·파일 삭제.
   - 이 테스트 기록은 4번 truncate 때 서버 DB에서 사라진다.

### 당일 (저장 중단 약 15~30분)

3. **공지**: "HH:MM~HH:MM 저장 금지(조회는 가능)" + 새 주소 `http://<서버주소>:8090`
   - 새 주소는 http 라 브라우저에 "주의 요함"이 뜨고, 홈 화면 앱 설치가 안 됨을 함께 안내.
4. **DB 옮기기** (Supabase 접속값은 대시보드 › Connect › Session pooler)
   ```bash
   export PGPASSWORD='<Supabase DB 비밀번호>'
   docker run --rm -e PGPASSWORD postgres:17 pg_dump \
     -h aws-1-ap-southeast-2.pooler.supabase.com -p 5432 -U postgres.<ref> -d postgres \
     --data-only --no-owner \
     -t public.vehicles -t public.routes -t public.daepyecha_confirmations \
     -t public.checklist_confirmations -t public.front_car_log > ~/supa.sql
   docker compose exec -T db psql -U app app -c \
     "truncate vehicles, routes, daepyecha_confirmations, checklist_confirmations, front_car_log"
   docker compose exec -T db psql -v ON_ERROR_STOP=1 -U app app < ~/supa.sql
   ```
   - `db.<ref>.supabase.co` 직접 주소는 IPv6 전용이라 풀러 주소를 씀.
   - `supa.sql` 은 서명까지 든 전체 데이터라 **저장소 폴더 밖(홈)에** 만든다(폴더 안에 두면 다음 `--build` 때 이미지에 들어감). 6번 통과 후 `rm ~/supa.sql`.
5. **PDF 나머지 받기** (전날 이후 생긴 것만)
   ```bash
   docker compose exec -T web node scripts/migrate-storage.mjs
   ```
6. **검증** — `검증 통과` 가 안 나오면 **여기서 중단**하고 공지 철회(사용자는 계속 Vercel 사용).
   ```bash
   docker compose exec -T -e SUPABASE_DB_HOST=aws-1-ap-southeast-2.pooler.supabase.com \
     -e SUPABASE_DB_PORT=5432 -e SUPABASE_DB_USER=postgres.<ref> -e SUPABASE_DB_PASSWORD="$PGPASSWORD" \
     web node scripts/verify-migration.mjs
   ```
7. **실사용 확인** (휴대폰, `http://<서버주소>:8090`) — 사진 업로드는 2-1에서 이미 확인함
   - 자재 지급확인서: 기존 PDF 열기, 신규 저장 1건
   - 설치완료 체크리스트: 기존 PDF 열기
   - 버스 검색(끝 4자리), 관리자 차량 검색
8. **Vercel 주소를 새 주소로 넘기기** (PC에서)
   - **되돌리기 대비**: 먼저 Vercel 대시보드 › 프로젝트 › Deployments 에서 지금 Production 배포를 기억해 둔다.
   - `vercel.json` 에 추가:
     ```json
     "redirects": [{ "source": "/(.*)", "destination": "http://<서버주소>:8090/$1", "permanent": false }]
     ```
   - GitHub Actions 워크플로 2개(`.github/workflows/seed-front-car.yml`, `purge-front-car.yml`) 삭제
   - 커밋 후 `git push origin main` (Vercel 자동 배포), `git push atec main`
8-1. **빠진 기록 최종 확인** — 덤프(4번) 이후 Vercel 에서 저장·수정된 건이 있으면 여기서 잡힌다.
   ```bash
   # 6번과 같은 명령으로 verify-migration.mjs 실행
   ```
   - `서버에 없음` / `옛 버전` 이 나오면: 같은 명령 끝에 `--fix` 를 붙여 실행 →
     `docker compose exec -T web node scripts/migrate-storage.mjs` → 다시 검증해서 `검증 통과` 확인.
     (`--fix` 는 해당 기록만 Supabase 에서 골라 복사하고, 전환 후 서버에 새로 저장된 건은 건드리지 않음)
9. **스케줄 등록** (서버)
   ```bash
   chmod +x deploy/backup.sh
   crontab -l            # 기존 것 있으면 deploy/crontab.txt 와 합쳐서
   crontab deploy/crontab.txt
   sudo systemctl enable docker
   deploy/backup.sh      # 첫 백업 바로 한 번
   ```

### 되돌리기 (당일만)

- 8번 전: 사용자 쪽은 아무것도 안 바뀜 → 공지만 철회.
- 8번 후 문제 발견: **Vercel 대시보드 › Deployments › 8번 전에 기억해 둔 배포 › ⋯ › Instant Rollback(Promote)**.
  사용자는 바로 예전 Vercel+Supabase 로 돌아간다.
  - ⚠️ 리다이렉트 커밋만 git 으로 되돌려 푸시하면 **안 됨** — 회사 서버용 코드가 Vercel 에 남아 전부 오류.
  - 그 사이 회사 서버에 저장된 건은 Supabase에 없으므로 **당일 안에만** 되돌린다.
  - 되돌린 뒤에는 다시 전환할 때까지 `origin` 푸시 금지(위 푸시 규칙).

## 백업과 복원

- 매일 03:00 `~/myapp-backup/YYYY-MM-DD/` 에 `db.sql.gz`, `files.tar.gz` (14일 보관).
- 같은 디스크라 서버 고장엔 소용없음 → **주 1회 다른 곳(NAS 등)에 복사** 권장.

**DB 복원**
```bash
cd ~/bustime_atec
docker compose stop web
docker compose exec -T db psql -U app -d postgres -c "drop database app" -c "create database app owner app"
gunzip -c ~/myapp-backup/<날짜>/db.sql.gz | docker compose exec -T db psql -U app app
docker compose start web
```

**파일 복원**
```bash
docker compose stop web
docker run --rm -i -v myapp_data:/d postgres:17 tar xzf - -C /d < ~/myapp-backup/<날짜>/files.tar.gz
docker compose start web
```
